# 第一次维护GitHub项目

你现在维护的是Strata的社区Fork。主项目作者和第三方版权保留在LICENSE/NOTICE中，本分支的新增工作说明在本目录。维护者：GLCdz。

- **仓库 / Repository**：代码、说明和修改记录所在的项目。
- **Commit**：保存一次有说明的修改记录。
- **Branch**：独立的一条开发线，适合试验新改动。
- **Push**：将本地提交上传到GitHub。
- **Pull Request / PR**：请其他人检查并合并某条分支的修改。
- **Release**：给一组已经验证的提交命名、写版本说明，便于用户下载和引用。

## 发布后的日常操作

1. 项目首页README是用户入口；V100特有说明在community/v100。
2. 小的文字修改可以在GitHub文件页点铅笔，保存前检查差异。
3. 代码改动先开分支，保留测试证据，再合并；不要在生产运行目录直接做发布操作。
4. 分享结果时附硬件、模型、输入长度、采样、缓存命中、样本数；不把单任务最高速度写成全任务保证。
5. 更新上游前先保留当前提交。上游版本改变后要重编译和复测，不能把旧版本验收当新版本验收。
6. Release可从仓库右侧Releases进入，选择已经验证的提交，再写适用硬件、改动、测试和限制。首版以源码为主，不承诺未验证的跨平台二进制。

原始实验和生产配置保持私有。本仓库只提交明确选择的community文件、源码和必要文档；不要使用git add .把运行配置、API密钥、会话记录或模型文件一起加入。

向上游贡献时，先查已有Issue/PR并按原AGENTS.md与docs/COMMUNITY_BENCHMARKS.md准备；本次发布没有自动向上游发消息或请求审查。
